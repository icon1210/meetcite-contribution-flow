## 1. Initial problem identification

* **Objective.** Address slow manual minutes, AI summaries that state things nobody said, and recurring meetings
  that lose track of decisions.
* **Evidence.** The problem and research question are in the README "The problem" section **[Git]**. The work
  started from a project specification PDF supplied on 8 Oct 2026 **[Session log]**. Who wrote the specification is
  not recorded in this repository.
* **Contributors.** Group 8 (specification). Individual authorship has not been verified.

## 2. Product concept and vision

* **Objective.** "Evidence-grounded" minutes: every point cites the transcript lines it came from, and a second
  pass checks each point against those lines.
* **Decisions.** On 8 Oct the owner asked for "more detailed" minutes than other meeting tools produce, with real
  speaker names **[Session log]**. On 11 Oct the owner proposed following a meeting "from start to finish", which
  became series memory **[Session log]**.
* **Contributors.** Olayinka (direction); Claude Code (design detail).

## 3. Requirements gathering

* **Implementation.** The specification was turned into features and checked against it on 8 and 9 Oct, and again
  against a group draft document on 9 Oct **[Session log]**. On 12 Oct it was checked against the university's
  specification guidelines **[Session log]**.
* **Files.** `docs/AUDIT.md` (requirement-by-requirement check) **[Git]**.

## 4. Technology selection

* **Choices.** Python FastAPI, React with TypeScript, SQLite with Alembic, faster-whisper, pyannote, a local Llama
  model, and later AssemblyAI with Claude **[Git]**.
* **Decisions.** Typed languages and automated tests were used throughout so errors are caught early. SQLite was
  chosen because one server is enough for a university-scale pilot. Local AI keeps data on the machine **[Retrospective]**.
* **Contributors.** Proposed by Claude Code, accepted by Olayinka.

## 5. Initial architecture

* **Implementation.** A web app talks to an API. A background worker runs the processing pipeline in stages, saving
  each stage's output so a failed job resumes instead of starting again **[Git]**.
* **Files.** `backend/app/main.py`, `backend/app/pipeline/runner.py`, `backend/app/jobs.py`, `backend/alembic/` **[Git]**.
* **Diagrams.** [ARCHITECTURE.md](ARCHITECTURE.md).

## 6. Frontend development

* **Implementation.**
  * Pages: landing, sign-in, dashboard, upload, record, meeting (11 tabs), series.
  * Mindy, an animated mascot that shows progress and explains errors (requested 11 Oct **[Session log]**).
  * A colourful landing page with motion (requested 9 Oct **[Session log]**).
* **Files.** `frontend/src/pages/`, `frontend/src/components/`, `Buddy.tsx`, `landing.css` **[Git]**.

## 7. Backend development

* **Implementation.**
  * REST API with 34 endpoints across 6 routers: auth, meetings, claims, edits, series, live.
  * JWT sign-in, an optional sign-up code and login rate limiting.
  * 11 database tables, created by 4 migrations.
* **Files.** `backend/app/routers/`, `models.py`, `security.py`, `ratelimit.py`, `alembic/versions/0001`–`0004` **[Git]**.
* **Challenges.** A sign-in failure was reported on 8 Oct and fixed **[Session log]**.

## 8. AI integration

* **Implementation.** Two interchangeable modes, chosen by one setting **[Git]**:
  * **Local:** faster-whisper, pyannote and Ollama with Llama 3.1.
  * **Cloud:** AssemblyAI and Claude.
* **Challenge and solution.** Local transcription was too slow (reported 8 and 9 Oct **[Session log]**), so cloud
  mode was added. An 88-minute recording then took about 3 minutes end to end **[Retrospective]**, based on the
  session record. There is no published benchmark yet **[Planned]**.
* **Files.** `pipeline/llm_clients.py`, `pipeline/cloud_transcribe.py`, `pipeline/gpu.py`, `config.py` **[Git]**.

## 9. Transcription

* **Implementation.**
  * FFmpeg converts audio to 16 kHz mono.
  * The audio is transcribed and speakers are separated.
  * Alignment starts a new transcript line after a 2-second pause or every 30 seconds.
  * Speaker names are suggested from what people say ("Hi, I'm…").
* **Files.** `preprocess.py`, `transcribe.py`, `diarize.py`, `align.py`, `names.py`, `tests/test_preprocess.py`,
  `test_align_chunking.py` **[Git]**.
* **Assigned owners.** Pascal (transcription) and Emmanuel (media processing), from Oct 2026. No contributions from
  them are in Git yet.

## 10. Meeting summarisation

* **Implementation.**
  * Map-reduce summarisation: chunk summaries are combined into minutes, decisions and action items.
  * The output is validated JSON (`summary_schema.py`).
  * Two research configurations:
    * **C1:** plain summary.
    * **C2:** every point cites transcript line IDs.
  * There is also a BART baseline.
* **Challenges.** Long generations sometimes ran away. Output caps, retries and per-stage caching fixed this **[Git]**
  (`llm_max_output_tokens`, `llm_max_retries`).
* **Files.** `summarize_llm.py`, `summarize_bart.py`, `chunking.py`, `extract_rules.py`, `tests/test_summarization.py` **[Git]**.

## 11. Evidence grounding and verification

* **Implementation.**
  * A second pass labels each point **supported**, **partly supported** or **not supported** by its cited lines.
  * Without an AI model, a word-overlap fallback applies the same labels: 60% overlap or more is supported, 30% or
    more is partly supported.
  * People can review flagged claims; reviews are stored in `claim_reviews`.
* **Files.** `verify.py`, `routers/claims.py`, `EvidenceTab`, `tests/test_verify.py` **[Git]**.

## 12. Series memory and live captions

* **Series memory.** Meetings in a series share open actions and a decision history, and changed decisions are
  flagged with both sources (`continuity.py`, migration `0004`) **[Git]**.
* **Live captions.** Captions appear while recording, using AssemblyAI streaming with a 60-second token, so the API
  key never reaches the browser (`routers/live.py`, `useLiveCaptions.ts`, `tests/test_live.py`) **[Git]**. They were
  tested by the owner on 11 Oct **[Session log]**.
* **Also included.** Agenda coverage, a follow-up email draft and calendar (`.ics`) reminders **[Git]**.

## Repository maintenance: student IDs removed from history (13 November 2026)

A group document (`docs/MeetMind_Viva_Guides.pdf`) had been committed in the rename commit on 13 October 2026,
before the rule that keeps group documents out of the repository existed. It contained the five members' student
ID numbers.

To protect that personal data, the file was removed from every commit with `git filter-branch`, with the owner's
approval. Nothing else changed: every commit kept its original author, date, message and co-author line, which was
verified by comparing them before and after.

Because Git identifies commits by their content, commits from the rename onwards received new IDs. The tags were
moved to the matching new commits, and the IDs in these documents are the new ones. A full backup of the repository
as it was before the change is kept privately.

## Lessons learned [Retrospective]

* **Speed versus privacy.** Cloud mode is fast but sends data to third parties. Both modes are kept, and the study
  sends only public AMI data to the cloud.
* **Never guess.** Unknown speaker names, vague deadlines and unsupported claims are flagged or left blank rather
  than invented.
* **Test what users see.** Browser tests caught problems that unit tests missed.
* **Record work as it happens.** Building most of the prototype before the repository existed left a gap in the
  history. From now on every change goes through a branch and a pull request.
